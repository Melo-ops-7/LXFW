# 部署运行指南

## 环境要求

- Python 3.10+（本机已验证 3.10.4）
- 依赖：`pip install -r backend/requirements.txt`（fastapi / uvicorn / httpx / pydantic）
- Dify（可选，已部署并接入 LLM 插件；不配置时系统自动降级运行）
- 无需 Node.js、无需数据库服务（SQLite 内置）

## 一、启动后端（含前端）

```bat
scripts\start_backend.bat
```

或手动：

```bat
cd backend
python -X utf8 -m uvicorn main:app --host 0.0.0.0 --port 8010
```

首次启动自动创建 `backend/xinxifang.db`（12 张表）并写入种子数据。

访问：
- 官网首页 http://localhost:8010/
- 学生端 http://localhost:8010/student.html
- 员工后台 http://localhost:8010/staff.html
- Swagger http://localhost:8010/docs

> 端口说明：本机 8000 已被旧项目占用，故用 8010。改端口需同步修改
> start_backend.bat、scripts/test_api.py、dify/*.yml 中 HTTP 节点 URL。

## 二、接入 Dify（获得完整 AI 能力）

按 `docs/Dify接入指南.md` 四步操作：
1. 创建 4 个知识库（knowledge/ 目录文件，FAQ 用 Q&A 分段模式，embedding 选 bge-m3 等中文模型）
2. 导入 dify/ 下 3 个 Chatflow DSL
3. 每个应用：选你的 LLM 插件模型、绑定知识库、核对 HTTP 节点地址（host.docker.internal:8010）
4. 生成 3 个应用 API Key → 填入 backend/.env（复制 .env.example）→ 重启后端

验证：员工后台（admin）→「系统健康」页可看到三个 Agent 的集成状态。

## 四、常见问题

| 现象 | 处理 |
|---|---|
| 端口被占用 | 换端口并同步修改三处配置（见上） |
| Dify HTTP 节点调用失败 | Docker 版 Dify 用 host.docker.internal 而非 localhost；确认后端 --host 0.0.0.0；核对 X-API-Key |
| 对话回复带「降级」提示 | backend/.env 未配置对应 Agent 的 API Key，或 Dify 不可达 |
| 知识库答非所问 | 更换中文 embedding 模型（bge-m3）；调 topK=4~5、score阈值0.4；FAQ 用 Q&A 分段 |
| 想重置演示数据 | 停后端 → 删除 backend/xinxifang.db → 重启自动重建 |
| 中文乱码 | 用 python -X utf8 启动；bat 脚本已含 chcp 65001 |

## 五、生产化建议（当前为演示级）

- 登录令牌改为 JWT + 刷新机制；密码哈希升级 bcrypt
- CORS 收敛来源；HTTPS；Dify Key 与 TOOL_API_KEY 改强随机值
- SQLite 换 PostgreSQL/MySQL（SQL 已参数化，迁移成本低）
- 高危预警通知接入钉钉/短信实际触达（当前为落库+后台展示）
